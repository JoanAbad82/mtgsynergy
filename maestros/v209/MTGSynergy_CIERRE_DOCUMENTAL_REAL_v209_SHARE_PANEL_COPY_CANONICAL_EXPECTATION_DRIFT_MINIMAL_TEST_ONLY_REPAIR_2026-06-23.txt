8. PREVENCIÓN DE FALLOS Y LECCIONES OPERATIVAS
=====================================================================

A. ERR trap y comandos con salida no cero esperada
Cuando existe un trap ERR global, una salida no cero esperada no debe ejecutarse como comando desnudo. Debe capturarse mediante una estructura if/else para impedir que el trap convierta una comprobación válida en fallo de fase.

Regla preservada:
- expected nonzero exit -> capturar en if/else
- no confiar solo en set +e alrededor de una comprobación cuando el trap ERR sigue activo

B. Comprobación de aplicabilidad de un patch ya materializado
Cuando el patch ya está aplicado en el worktree, git apply --check contra el worktree modificado puede fallar correctamente porque la línea antigua ya no existe.

Regla preservada:
- para comprobar el patch contra la baseline limpia del index, usar git apply --check --cached
- interpretar el fallo de git apply --check sobre el worktree modificado como esperado, no como evidencia automática de patch inválido

C. Separación entre copy runtime y expectativa de test
Antes de editar un componente visible, comparar:
- copy servido por runtime
- copy esperado por el test
- contrato UI vigente

Si runtime y contrato coinciden, la reparación debe limitarse a la expectativa obsoleta.

D. Disciplina de alcance
Una deriva de copy localizada no autoriza:
- refactor del componente
- cambios semánticos
- reapertura de scoring
- limpieza lateral
- reparación de deudas independientes
